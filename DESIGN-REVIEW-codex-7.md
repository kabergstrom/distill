codex
1. **CRITICAL — §5, §12, §18: the source-fingerprint tie is not representable by the normative identity API.** `CompilationIdentity` contains manifests, features, cfgs, target, rustc, and algorithm version, but no strengthened `ngp-source-hash`; no layout-table declaration carries one either. A foreign layout table generated from older Rust sources can therefore have the same declared identity after source-only edits and pass the per-target gate, causing current logical data to be encoded using stale field/layout semantics. Add an explicit source fingerprint to schema records, layout-table identities, module attestation, and the target-definition hash; bind every layout entry to `(source_fingerprint, algorithm_version, type_uuid, logical_hash)`.

2. **CRITICAL — §12: `LayoutHash` does not cover all determinants of the cached fixup plan or nested wire encoding.** `FixupPlan` is cached by `(type, layout_hash)`, but DSWL records wire offsets/sizes/alignment, omits native destination offsets and skipped-field layout, and records native tag encodings only for fully-flat enums. Its indirection payload specifies only a slot kind, without a normative child-node encoding. For example, enlarging a skipped field can shift a later native field while leaving the wire tree unchanged; the cached plan then writes that field at the old native offset. Likewise, a relayout of an enum nested under `Vec` can change variable-element stride without changing the declared root slot payload. Either hash every native fixup determinant and recursively encode all container children, including every `NativeTagWrite`, or split `WireLayoutHash` from a native `FixupPlanKey` tied to the compilation epoch.

3. **CRITICAL — §3, §9, §15: code and tool content hashes have a TOCTOU cache-poisoning race.** The design hashes a dylib/executable path and separately loads or executes that path. If a supervisor replaces the dylib between hashing and `dlopen`, code B can run under code A’s cache key. The same race exists between hashing a registered tool and spawning it, recording A’s hash for B’s output. Later lookups under A can silently reuse B’s artifact. Load/execute an immutable content-addressed copy or a verified open file descriptor, and ensure the bytes hashed are exactly the bytes loaded/executed.

4. **CRITICAL — §10, §11: treating migration-defaulted tags as absent silently under-approximates queries.** `load_current` yields a current-schema value containing the default, while the tag index deliberately omits it. If a migration adds `category = "enemy"` by parent default, an atlas processor querying `tag(category=enemy)` silently excludes all migrated assets even though their runtime values contain that tag. Index the actual current value, or define absence in the value/schema itself—such as `Option::None`—rather than maintaining query semantics different from loaded-value semantics.

5. **CRITICAL — §12, §15–§18: target-specific content is not bound at the consumption boundary.** Artifacts intentionally omit a target field, but the declared pack manifest contains no `target_def_hash` or bound identity, and the RPC `Hub` exposes no target negotiation despite saying the target is declared at connect. A Metal and DX12 pack can have identical logical/layout hashes while containing different shader blobs; mounting the wrong pack passes every declared artifact check and serves wrong backend content. Put the target-definition hash and bound compilation/layout identity in the pack manifest header and verify them at open; add an explicit target handshake to the RPC bootstrap.

6. **HIGH — §3, §11: the declared module ABI cannot provide the promised bootstrap or panic containment.** The host must invoke Rust-ABI `identity() -> CompilationIdentity`—returning `String` and `BTreeSet`—before it has verified the same-rustc contract. Moreover, `identity` and `unload` cannot return the promised error status, and `MigrationFn` is a directly registered Rust function pointer with no enforced module-side wrapper. Use a minimal C-ABI bootstrap returning serialized identity bytes through caller-owned buffers and explicit status codes; register only module-generated erased callback wrappers that catch panics inside the dylib.

7. **HIGH — §5, §11, §13: `LoadContext` does not enforce a coherent schema/module epoch.** It independently accepts a `MetadataSnapshot`, the “live” `SchemaRegistry`, and a `ModuleHandle`. A caller can pair a new current schema with an old module’s migration/default tables, even though each was valid when published separately. Make these fields come from one immutable `BuildEpoch`/registry snapshot whose schema, module, pipeline map, source fingerprint, and compilation identity were validated together.

8. **HIGH — §9, §10, §13, §16–§17: same-bundle `local_id` queries lack their required scope.** `AssetQuery.local_id` means “within the referencing bundle,” but `MetadataSnapshot::query`, RPC `Snapshot.query`, pack-root evaluation, and `TraceOp::Query` contain no referencing bundle. Two bundles containing `override/metal` therefore cannot be distinguished during query execution or trace revalidation. Add an explicit query scope/origin bundle to evaluation and traces, and reject bundle-relative selectors from context-free APIs.

9. **HIGH — §8, §13, §18: normative path APIs erase required ambiguity and I/O errors.** Multiple roots make duplicate relative paths an error, yet `MetadataSnapshot::resolve_path` returns `Option`, `ImportContext::probe` returns `bool`, and `enumerate` returns `Vec`. They cannot distinguish missing from ambiguous, inaccessible, or symlink-invalid paths; a watched import can record a false miss or silently select one root. Return `Result` with explicit `Missing/Ambiguous/IoError`, and either root-qualify recorded paths or retain all candidate root identities.

10. **HIGH — §6, §8, §17: initial import, re-import, and watch configuration are unreachable through the declared RPC.** `Hub.import(base, path, settings)` supplies neither `Importer::ID`, destination/prior bundle, nor `watch`; importer registration declares no extension matcher. The generic `Settings` type also has no required watch field, despite the prose saying settings set it. Replace this with an `ImportRequest` carrying importer ID, sources, optional prior/destination bundle, typed settings, and watch policy; add an explicit re-import operation keyed by the bundle or `ImportRecord`.

11. **HIGH — §7, §9: processors cannot create a reachable reference to an extra output.** Extras are reachable only when a built artifact embeds their derived UUID, but `ProcessContext` exposes no parent UUID or output-reference method, and `Outputs::extra` returns nothing. The processor therefore cannot compute or obtain the `AssetRef<T>` needed to place the child in its primary output. Have `extra` return the typed derived reference, or expose `ctx.output_ref::<T>(key)` after validating the static declaration.

12. **HIGH — §4, §7, §9, §13: uniqueness checks cover bundle UUIDs but not other identity domains.** Two distinct bundles may retain the same asset UUID, two code types may copy the same `TypeUuid`, and a UUIDv5 child may collide with an authored UUID or an existing child mapping. The singular metadata maps then have no defined safe behavior. Require global duplicate detection for asset and type UUIDs, verify derived rows against authored and derived namespaces at commit, and reject conflicting mappings rather than relying on UUID collision improbability.

13. **HIGH — §12: fixup validation omits Rust scalar validity.** `FlatCopy` can create invalid `bool` or `char` values, while the listed validation covers bounds, alignment, UTF-8, discriminants, and resource caps only. A malformed but correctly hashed artifact—or an encoder defect—can therefore cause UB when the destination is assumed initialized. Add scalar-validation operations for every Rust type with restricted bit patterns before writing or assuming initialization.

14. **HIGH — §13, §15: loader versions narrow from `u64` to `u32` at `AssetStorage`.** `InputVersion` and manifest adoption use `u64`, but `update`, `commit`, and `free` accept `u32`. After wrap/truncation, different input versions become indistinguishable and stale commits or frees can target the wrong generation. Pass `InputVersion` or `u64` end to end.

15. **HIGH — §17: long-running authoring operations do not carry the required version precondition.** `Hub.operation(op)` has no declared `base`, although rename fixups and disk migration rewrite files and all authoring writes are said to be version-preconditioned. A concurrent editor write can be overwritten by a later per-file step based on stale content. Carry an explicit base version and expected per-file content hash; stop and report a conflict when either changes.

16. **HIGH — §6, §9, §12: DSTL does not pin canonical ordering for unordered data.** Bundle JSON sorts map entries, but artifact encoding only says maps are flattened as pairs, and `load_deps` likewise has no sorting/deduplication rule. A processor-produced `HashMap` can iterate in randomized order, producing different CKeys and pack bytes for identical inputs; reference traversal through it can also reorder the dependency header. Require map entries to be sorted by canonical encoded key bytes and load-dependency UUIDs to be sorted and deduplicated.

17. **HIGH — §3, §5: exact feature-identity comparison has no defined package scope.** The prose requires equality while earlier limiting the ABI invariant to shared dependencies. A pipeline-root build naturally enables pipeline-only package features that source-walk over the asset-types crate does not, so comparing the full declared set rejects valid modules; informally ignoring extras can miss a shared-ABI feature mismatch. Define the exact ABI/layout dependency closure whose `(package, feature)` and cfg sets are compared, separately from pipeline-only code identity covered by the dylib hash.

18. **MEDIUM — §3, §6, §11: the defaults registration signature cannot express the promised table shape.** `defaults<T: AssetType>` promises an optional parent default requiring `T: Default` plus independently available field defaults, but its bound neither requires `Default` nor exposes a field-only registration mode. Adding `T: Default` would incorrectly prevent registering valid field defaults for a non-`Default` parent. Register a macro-generated `DefaultTable<T>` with an optional parent writer and explicit per-path writers.

19. **LOW — §9, §12, §16: cross-asset CKey deduplication is contradicted by the artifact bytes.** Because `asset_uuid` is inside the raw DSTL bytes, identical values belonging to different assets necessarily have different CKeys, contrary to “dedup across versions and assets.” Narrow the claim to same-asset/version reuse, or introduce separately hashed identity-neutral payload chunks if cross-asset dedup is required.
