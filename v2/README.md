# distill v2

Implementation of `../DESIGN.md` — the distill v2 asset-pipeline daemon.

Every crate maps to a section of the design document; the document is
normative and the tests here verify its specified behaviour (happy paths,
edge cases, and negatives), test-first.

| Crate | Design section |
|---|---|
| `distill-core` | §5 the one encoding, `Domain` digests (XXH3-128), shared file header, bootstrap spec; identity newtypes (§7) |
| `distill-json` | §6 canonical JSON, `AuthoredValue` |
| `distill-schema` | §5 daemon-side schema services over `ngp-schema` (which holds the model, logical hash and snapshot codec): the schema file authority (`ProjectSchemaAuthority`), registry, tag extraction |
| `distill-bundle` | §6 bundle file format |
| `distill-migrate` | §11 automatic migration planner, plan validation and executor |
| `distill-wire` | §12 wire layout derivation and layout encoding, artifact image, `encode_value`, fixup plans and executor |
| `distill-store` | §13 metadata store + log-structured CAS |
| `distill-build` | §8 import, §9 processing, §10 dependencies |
| `distill-asset` | §4 asset types: `AssetType` (impls generated by newgameplus source-walk, `ngp_asset_types.rs`; `#[derive(Asset)]` is inert), the reflection interpreter over the walked schema, runtime descriptors |
| `distill-protocol` | §17 protocol data types (requests, answers, errors, `state`), shared by client, server and loader |
| `distill-loader` | §15 runtime loader; feature `rpc` (default) adds `RpcIo` and authoring over `distill-client` |
| `distill-pack` | §16 pack reader (`PackfileIO`) |
| `distill-pack-build` | §16 pack writer and publish |
| `distill-client` | §17 Cap'n Proto schema, bindings and client transport |
| `distill-rpc` | §17 server: capabilities, publish, server transport |
| `distill-daemon` | §3 |

A runtime reading packs only (the loader without `rpc`) links `distill-asset`,
`distill-core`, `distill-loader`, `distill-pack`, `distill-protocol` and
`distill-wire`, and newgameplus's `ngp-schema`, which still names `distill-json`
(its text codecs: cooked prefabs are parsed from text until newgameplus GAP 23
§17.11 step 5).

The schema model (logical hash, snapshot codec; `SchemaNode`, `Value` and
`Patch` from `ngp-value`, re-exported) lives in newgameplus's `ngp-schema`,
shared with source-walk and the engine
(§5, "One model, split — not a second one"). `distill-schema` holds only the
daemon-side services over it.

Build/test with `nix run nixpkgs#cargo -- test` from this directory.
