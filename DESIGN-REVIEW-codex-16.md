All six round-15 folds appear textually. The findings below concern remaining completeness and internal-consistency gaps, not the settled decisions themselves.

1. **CRITICAL — §5, §12 — Generated-table identity omits `SkipDefaultId`.** Fixup plans execute `WriteSkipDefault { writer: SkipDefaultId }`, but the repaired native identity covers only `CtorId` and `DropId` assignments. Reordering two same-layout skipped fields can therefore leave the cache key unchanged while making an old plan call the wrong default writer or drop function, causing type confusion or memory corruption. **Fix direction:** include every plan-interpreted table index—especially `SkipDefaultId` and its paired drop—in the native identity.

2. **CRITICAL — §5, §12 — Pairing table IDs with DSWL identity is not injective over callback semantics.** Two different Rust types can have identical DSWL trees while differing in `Drop`, `Hash`, `Eq`, container type, or other monomorphized behavior. Swapping their `CtorId` or `DropId` assignments leaves the stated `(ID, DSWL identity)` measurement unchanged, yet cached plans can invoke the wrong callback. **Fix direction:** give each generated entry a collision-free semantic identity incorporating its nominal monomorphized type, owning structural path/role, and code-generation identity—or conservatively include the supplying binary/module content identity in the plan-cache key.

3. **CRITICAL — §3, §4, §15 — Runtime descriptors become dangling across game-module reloads.** `Loader::register_types` stores `'static` descriptors containing function pointers into the consuming binary, while the asset-types crate is linked into the reloadable game module. No unregister/epoch/clear protocol drains fixup plans, descriptors, constructed `Box<dyn Any>` values, and drop glue before `dlclose`. “Caller responsible for cleanup” is not implementable through the declared API except by destroying the entire loader and storage, and §15 nevertheless says asset reload composes with module reload. **Fix direction:** bind registrations and loaded values to a game-module epoch with an explicit drain/unregister barrier, or require all descriptors and callbacks to reside in a non-unloaded engine binary.

4. **HIGH — §5, §16, §17 — “Measured layout digest” has two incompatible meanings.** The native identity includes binary-local constructor/drop table assignments, but pack mounting and `Root.connect` compare the pack/daemon layout-table measurement with the game’s measurement. Source-walk layout tables have no binary-local table assignment, and independently built game and pipeline binaries need not assign equal IDs. Thus the required equality is either impossible or silently drops part of the claimed digest. **Fix direction:** define separate canonical identities: a cross-binary layout-only measurement for registration/connect/pack compatibility, and a binary-local fixup-table identity used only for plan caching.

5. **HIGH — §4, §12, §15 — `AssetRuntimeDescriptor` is insufficient to compile or return a fixed-up value.** It exposes a digest and callback tables, but not the native layout tree/descriptors needed to derive destination offsets, tag writes, skip positions, or expected logical/layout hashes. Nor does it provide the typed allocation/type-erasure callback needed to produce the `Box<dyn Any>` required by `AssetStorage::update`. A digest cannot reconstruct these facts. **Fix direction:** add generated native-layout/fixup metadata, expected logical/layout identities, and a type-erasure/allocation boundary—or replace the low-level tables with a generated per-type decode/fixup function returning an owned erased value.

6. **HIGH — §5, §18, §19 — Per-target equality checks only facts that DSLH deliberately retains.** Equal DSLH trees do not prove equal type UUIDs, `build_only`, or `tag`, because those facts are beside or excluded from the logical hash. Target-dependent `cfg_attr` can therefore pass the stated equality gate while producing facts that the single shared `TypeDef`, pipeline map, derived namespace, and load-closure policy cannot represent. **Fix direction:** compare a full target-invariant registry projection containing type UUIDs, logical ASTs, and unhashed policy/index attributes; continue excluding the latter from migration identity.

7. **HIGH — §7, §9, §12, §16 — Derived extras have no defined `authored_type`.** Every DSTL header and pack manifest requires authored, terminal, and encoded type UUIDs, but an extra output has no authored entry. The output declaration provides only the extra’s output type, and “type uuids” in result tables never pins whether `authored_type` is the parent’s source type, the extra type, or something else. Cache-hit and loader header validation can therefore be implemented incompatibly. **Fix direction:** define derived-output header semantics explicitly, such as `authored_type = terminal_type = encoded_type = declared extra type`, or add an explicit artifact-kind/optional-authored-type field.

8. **HIGH — §7, §13, §15 — Unpublishable filesystem states break retry and version semantics.** Duplicate identities are rejected “before the version becomes queryable.” If the filesystem has changed but the daemon retains the prior published version, a resolve against that version reads different bytes and returns `Drifted`; `current` may still name the same old version, so retry-refreshed clients can loop forever at quiescence. Existing clients may also receive no versioned invalidation for the rejected state. **Fix direction:** publish a new poisoned/error input state, or advance a separate observed-input epoch, so affected resolves return a stable `Failed`/poison result and subscribers are notified while last-good artifacts remain available.

9. **HIGH — §13, §14, §18 — Downstream bundle metadata loses the physical root identity repaired in `files`.** `files` correctly keys on `(root id, path)`, but `bundles` still maps `bundle uuid → path` with no root. With the same logical path in two roots, UUID-based asset access still needs the owning physical file to verify and build its bytes; resolving the stored path through the logical index yields ambiguity or risks selecting the wrong file. **Fix direction:** store a physical file key `(root id, path)` or foreign key on every bundle row; derive path-query ambiguity separately.

10. **MEDIUM — §4, §9, §16 — `build_only` applicability is ambiguous after type-changing processing.** A closure node has an authored type and a terminal type. The specification does not say whether `A #[asset(build_only)] → B` is forbidden from shipping because `A` is build-only, allowed because runtime consumes `B`, or forbidden only when `B` is marked. **Fix direction:** define the check over explicit metadata—preferably whether either the authored asset policy or the declared derived-output policy forbids runtime reachability.

11. **MEDIUM — §6, §8 — The total-replacement fold lacks an enforceable namespace for daemon-owned entries.** `AssetEntry` has no role field, and importer `local_id`s are unrestricted. An importer can emit the same ID used by the Settings entry or `ImportRecord`; the document says importers never write those entries but specifies neither reserved IDs nor a fold-time collision error. **Fix direction:** reserve and validate daemon-owned local IDs, or move role metadata outside the ordinary asset namespace; reject all collisions explicitly.

12. **MEDIUM — §8, §20 — `Grouping::ByStem` is undefined across directories.** It groups by basename stem while output must land “beside its sources.” Two directories containing `foo.vert`/`foo.frag` can form one group with no unique destination, or different implementations can group globally versus per directory. **Fix direction:** define the key as `(root, directory, stem)` or reject groups spanning multiple physical directories.
