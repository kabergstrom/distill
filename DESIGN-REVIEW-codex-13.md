1. **HIGH — §8, §9, §10, §12:** The normative `DSBI` build-import key omits pipeline-map identity. A module reload can change referenced asset `R` from terminal type `T` to `U` while the referencing bundle, resolved UUID, and its logical/layout hashes remain unchanged. Although §10 says pipeline-map changes revalidate typed references, the cached key records only the resolved UUID, so the old artifact can hit and bypass that validation. The imported artifact’s own `terminal_type` can likewise change without changing its key; the new `asset_uuid` and `encoded_type` checks both still pass. Include a canonical pipeline-map hash in `DSBI`, or include the entry’s terminal type plus every typed resolution’s observed terminal type, and validate all header type fields on hits and publication.

2. **MEDIUM — §5, §18:** `Target` is declared `#[asset]` and “schema-described,” but `Target.apis` is a `BTreeSet<GraphicsApi>`. The serializable-kind list and logical grammar support `Vec`, arrays, and `HashMap`, but no set kind; artifact fixup also has no set constructor. Consequently the normative `Target` declaration is an extraction error before its new non-empty validation can run. Either represent APIs as a canonicalized, unique, non-empty `Vec`, or add set semantics throughout the logical grammar, JSON encoding, wire layout, migration, and constructor tables.

3. **MEDIUM — §12:** The framed rollback prose now requires a completed aggregate to push its whole-value drop glue, but the normative plan declarations provide no way to name that glue. `FixupPlan` contains only `ops`; `Recurse` carries only a `PlanId`; and `CtorId` covers container constructors. For a nested struct with custom `Drop`, followed by a later UTF-8 or scalar-validation failure, the executor cannot select the required whole-value drop thunk. Add a generated `DropId`/aggregate-drop table keyed by native layout identity, and attach the appropriate drop entry to each aggregate plan.

4. **MEDIUM — §12:** `FixupOp::SwitchVariant` cannot fully describe how to read its wire tag. `wire_tag` is only an offset, while `NativeTagWrite` describes the destination encoding. For an enum with a native one-byte direct tag but a divergent payload, the wire uses a canonical `u32` name-sorted index; the operation carries neither that source width/form nor an explicit wire-value-to-variant mapping. Add a `WireTagRead` description such as `CanonicalU32` or `Direct { size, signedness, values }`, separate from `NativeTagWrite`.

5. **MEDIUM — §7, §9, §13:** Derived-output identity is global and target-independent, but only the extra’s type—not its presence—is required to be target-invariant. A Vulkan-only processor may declare key `"reflection"` while the Metal chain does not. The snapshot-wide derived index then either claims a child that has no producing stage for Metal, contradicting the guarantee that remembered children always resolve, or must silently become target-scoped despite being declared otherwise. Require every parent type to expose the same extra-key/type set across all target chains, or explicitly target-scope the namespace index and child-resolution semantics.

6. **MEDIUM — §3, §8, §11:** Registry-key uniqueness is unspecified for importers, migration functions, tools, and default tables. A conventional map-backed implementation could silently overwrite a duplicate `Importer::ID` or migration function key. A watched re-import could then run the wrong importer and rewrite committed content without an ambiguity error. Define duplicate registration as an epoch-opening error for every single-owner key; retain multiplicity only where explicitly allowed, such as validators.

7. **LOW — §9, §13:** `Outputs::debug` accepts an unrestricted key and cannot report failure, while CAS records encode `out_key_len` as `u16` and result records use a keyed auxiliary table. An overlong or duplicate debug key is therefore a valid API input with no normative encoding. Bound debug keys, reject duplicates without truncation, and specify that violations fail result binding.

Remaining CRITICAL issues: none. Remaining HIGH issues: 1.
