Fixes 2–4, 6, and 7 are coherent as specified. Fixes 1 and 5 still have lifecycle/ownership gaps below.

1. **HIGH — §3, §12 — `CtorEntry::push` cannot uphold its panic ownership contract.**  
   `push` says ownership transfers only on `Ok`; on `Err`, the element remains the caller’s. For a map constructor, however, the thunk must move the key/value out of `elem` before calling potentially panicking `Hash`/`Eq`/insertion code. If that code panics, unwinding may drop or retain the moved value before `catch_unwind` returns `Err`; it cannot be restored generically. The executor then rolls back `elem` as instructed, potentially double-dropping it or an allocation now owned by the partial map—UB from safe user code with a panicking `Hash` implementation. There is also no declared abort operation for a partially filled `CtorCursor`. Change the contract so `push` consumes the source slot on entry regardless of result, make the cursor own all subsequent cleanup, and add an explicit no-unwind `abort/drop_cursor`. Require `finish` to leave `dst` untouched on failure. If ownership can genuinely vary, return an explicit consumed/retained disposition.

2. **HIGH — §7, §9, §13 — Current derived identities conflict with historical, monotone derived-output rows.**  
   Publication validates authored UUIDs only against the current epoch/input version’s derived set, while §13 calls derived-output rows monotone and CAS recovery reconstructs them from every retained historical result table. Suppose an extra key is removed—or its parent asset is deleted—then an authored asset adopts that former child UUID. Current publication accepts it because the child is no longer precomputed, but an old CAS result still reconstructs `child → (old parent, key)`. Authored lookup and derived lookup now both claim the UUID, so resolution becomes implementation-order-dependent or fails after a supposedly valid publication. Scope the authoritative reverse map to the input snapshot/pipeline map; historical result records may remain memo data but must not recreate live namespace claims. Recovery should rebuild result memos separately and derive each snapshot’s child map only from that snapshot’s authored assets and pipeline map. The alternative—permanent UUID tombstones—would need a reconstructible authored source, not disposable CAS history.

3. **MEDIUM — §7, §9, §13 — The derived-index recomputation cadence is contradictory.**  
   §7 requires validation at every input-version publication, but §9 says the complete index is derived “at every epoch publication,” and §13 describes it as “precomputed per epoch.” Asset creation/deletion does not necessarily rotate `PipelineEpoch`. Following §9/§13 literally, a bundle added under unchanged code has no precomputed children; its extra-output commit either fails verification or its child cannot resolve until an unrelated code reload. Define this as an input-versioned/snapshot index parameterized by that version’s pinned pipeline epoch, and update all three sections consistently.

4. **MEDIUM — §9 — The declared `Outputs` API cannot compute the UUID it promises to return.**  
   `Outputs::extra` must immediately return `AssetRef<T>(UUIDv5(parent_uuid, key))`, yet `Outputs::new()` receives no parent UUID, `Processor::process` receives only the typed value, and `ProcessContext` exposes no current-asset identity or output-builder factory. The concrete 16-byte `AssetRef` cannot be patched later after it has been embedded in the primary output. Have the host create an `Outputs` already bound to `(parent_uuid, OutputDecls)`, for example through `ctx.outputs()`, or expose `ctx.extra_ref(key)` and make direct unbound construction impossible.

5. **MEDIUM — §12 — Rollback has no declared drop path for skip defaults and arbitrary completed nodes.**  
   `WriteSkipDefault` may construct an arbitrary `Default` value with allocations or external resources, but it carries only a `SkipWriter`; neither the operation nor the declared skip table supplies a corresponding drop function. If that write succeeds and a later constructor/default fails, the generic executor cannot drop the skipped value because its type is absent from the schema. The same gap applies to nested schema structs/enums with custom `Drop`: container drops alone do not invoke the enclosing type’s drop glue. Extend generated tables and fixup ops with a `DropId` for every constructed node, including skipped fields, or explicitly forbid custom `Drop` where the executor cannot represent it.

6. **MEDIUM — §9, §18 — `TargetSelector.apis` has no normative match or overlap semantics.**  
   Both the target and selector contain API sets, but “present fields AND” does not say whether `{Vulkan}` matches a `{Vulkan, Dx12}` target by subset, intersection, or exact equality. Consequently selectors `{Vulkan}` and `{Dx12}` may be overlapping, disjoint, or nonmatching depending on implementation, changing the processor chain, derived UUID set, and backend selected for the same target definition. Specify the exact predicate and use that same predicate for registration overlap detection and pipeline-map construction.
