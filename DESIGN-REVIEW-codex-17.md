Review of [DESIGN.md](/Users/karl/Projects/distill/DESIGN.md):

1. CRITICAL — §3, §11, §13, §15 — `MetadataSnapshot` pins an `Arc<PipelineEpoch>` containing module registrations, yet reload drains only old-epoch jobs before `dlclose`. A live snapshot can therefore retain module-owned trait objects/function pointers after the code is unloaded; dropping or accessing that epoch later is use-after-`dlclose`. Returning `Drifted(Dylib)` does not make the retained objects safe. — Fix direction: either make snapshot leases pin module residency, or place module-owned state in a revocable synchronized cell where every access requires an epoch job guard; atomically revoke, wait for all guards, drop the objects, replace them with a daemon-owned tombstone, then call `unload`/`dlclose`.

2. CRITICAL — §4, §12, §22 — The descriptor still cannot supply the rollback `DropId`s that compiled plans require. `FixupPlan::whole_drop` needs the exact entry for each completed aggregate, but `NativeLayoutNode` annotates only `CtorId` and `SkipDefaultId`; `DropTable` has no key metadata and `fixup_identity` is only a digest, not a lookup map. `ConstructString` and `ConstructBlob` likewise expose no rollback-drop selection. Guessing positional IDs can invoke the wrong drop glue and corrupt memory. — Fix direction: annotate every applicable native node with `whole_drop: Option<DropId>` and give every non-ctor constructed leaf an explicit rollback drop ID or a normatively defined built-in drop operation. Include all such mappings in `fixup_identity`.

3. HIGH — §4, §5, §12 — `NativeLayoutNode` is not expressive enough to be the promised measured tree. `ScalarKind` contains only `Bool` and `Char`, so even the introductory `f32` field cannot be represented; arrays have no node; several nodes omit measured size/alignment; and “native field order” has no deterministic definition for reordered fields or equal-offset ZSTs. Separately, an artifact provides only a `layout_hash`, but plan compilation needs the corresponding wire tree—a hash is not that tree. — Fix direction: define a complete native grammar covering every primitive, arrays with length/stride, geometry for every node, and deterministic physical ordering with tie-breaking. Normatively derive the wire tree from it and require its computed `LayoutHash` to equal the artifact header before compiling a plan, or provide an authenticated `LayoutHash → wire tree` registry.

4. HIGH — §5, §12, §22 — The round-16 two-identity repair is contradicted inside the resolved ledger. One §22 entry says “native layout identity = the measured digest”; another says the measured digest covers `CtorId`/`DropId` assignment. Both contradict the normative rule that the cross-binary measured digest is layout-only and only `fixup_identity` contains `CtorId`/`DropId`/`SkipDefaultId`. These alternatives produce either unsatisfiable cross-binary checks or stale plans calling wrong table entries. — Fix direction: replace every remaining “native identity” reference with the exact named identity, and correct the two stale §22 statements to use `fixup_identity`, including `SkipDefaultId`.

5. HIGH — §3, §4, §5, §16, §17 — Registration exports and descriptors define per-type measured digests, but pack headers and `Root.connect` carry one unspecified “layout table measured digest.” There is no aggregate grammar, domain prefix, type-set coverage rule, or definition of whether the game must match the whole workspace registry, only registered types, or the pack closure. Different implementations can hash different sets while claiming the same check. — Fix direction: define a versioned aggregate such as a sorted, length-framed `(TypeUuid, per-type digest)` table with an explicit domain, and state exact missing/extra-type semantics at registration, connect, and pack mount. Per-type negotiation may be preferable when consumers legitimately compile subsets.

6. HIGH — §8, §13, §18, §20, §22 — Multi-root identity is erased from raw-file dependencies. `enumerate` returns `Vec<String>`, `FILQ` hashes only paths, and `FileDep` records no observed root, while `ByStem` now requires `(root, directory, stem)`. Moving identical bytes from root A to root B at the same logical path can leave every recorded result unchanged even though the output destination and group identity changed; the required root cannot even be recovered from the declared API. — Fix direction: use a canonical `RootedPath { root_id, path }` in enumeration results, listing hashes, source groups, and every file dependency whose semantics depend on the selected physical file.

7. HIGH — §5, §7, §9, §10, §13 — Canonical record encoding NFC-normalizes every string, but identifiers and tag/query values are otherwise compared as raw Rust strings, and UUIDv5’s output-key byte encoding is unspecified. Two distinct output keys such as precomposed and decomposed `é` can pass raw uniqueness checks, collapse in serialized output tables or DSSI inputs, yet mint different child UUIDs. Trace recovery can similarly normalize a tag query whose matching semantics were byte-exact. — Fix direction: require and store NFC at every identifier/query boundary, perform uniqueness after normalization, and define UUIDv5 names as the same normalized UTF-8 bytes; alternatively, stop normalizing strings whose runtime semantics are raw-byte-exact.

8. HIGH — §10, §13, §14, §18 — The supposedly pinned path rules do not reject absolute paths, `.`/`..`, empty components, NULs, or lexical root escape, and they do not specify rejection of two physical names within one root that normalize to the same NFC key. Because `files` keys on the normalized path, such collisions can overwrite observations before ambiguity is representable; traversal can also make recorded dependency keys differ from the file actually read. — Fix direction: define a total lexical path grammar with containment checks and reject canonicalization collisions during scans before inserting file rows.

9. HIGH — §7, §13, §15, §17 — Poisoned-version semantics are not representable consistently by the metadata API. A duplicate identity cannot be stored in the single-key `assets`/`bundles` maps, yet `MetadataSnapshot::entry` returns `Option<EntryMeta>` rather than an error. Implementations can retain one duplicate, omit both, or expose last-good metadata while only `resolve` reports poison. That lets editor, codegen, and query consumers observe mutually incompatible projections of the poisoned version. — Fix direction: give every namespace-facing snapshot operation a version-level poison error, including `entry`, and forbid exposure of normal indexes from a poisoned version. Define whether the poison is global or domain-scoped and apply that rule uniformly.

10. MEDIUM — §4, §15 — `AssetRuntimeDescriptor::finalize` returns `Box<dyn Any + Send + Sync>`, but `AssetType` requires only `'static` and `AssetStorage::update` accepts `Box<dyn Any>`. This silently imposes undeclared `Send + Sync` bounds, conflicting with the explicitly single-threaded engine model and likely excluding assets with thread-affine skipped/GPU fields. — Fix direction: return `Box<dyn Any>` or add and justify `Send + Sync` bounds throughout `AssetType`, storage, placeholders, and examples.

11. MEDIUM — §6, §8, §17, §22 — `$` reservation is enforced only by `ImportOutput::entry`. The general bundle parser, adoption, editor CRUD, and write API have no specified rejection semantics for hand-authored `$record`, `$settings`, or `$foo` entries. A spoofed `$record` can be mistaken for daemon-owned reimport state. — Fix direction: enforce the reserved prefix at every bundle creation/parse/edit boundary and require the two recognized IDs to have their exact built-in role and type; all other `$` IDs must be integrity errors.

12. MEDIUM — §5, §12 — Direct and niche discriminants are represented as `i128`, which cannot encode valid `repr(u128)` discriminants above `i128::MAX`; `NativeTagEncoding::Direct` also lacks an explicit signedness/raw-bit convention. Such enums are not rejected elsewhere, so exact measured-layout and tag-writing guarantees do not hold for the full Rust enum space. — Fix direction: carry discriminants as fixed-width raw `u128` bits plus width/signedness, or explicitly reject unsupported enum representations during extraction and macro expansion.
