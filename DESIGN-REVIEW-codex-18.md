1. **CRITICAL — §3, §4, §15. Placeholder ownership is both unimplementable and unload-unsafe.** `Loader::set_placeholder<T>(value: T)` supplies one non-`Clone` value, but deletion may require separate owned `Box<dyn Any>` values for multiple handles through `AssetStorage::update`. The API provides neither cloning, a factory, nor storage aliasing. It also does not associate the placeholder with `GameModuleEpoch`; its drop glue or `Any` vtable may reside in a subsequently unloaded game module, allowing use or drop after `dlclose`. **Fix direction:** register an epoch-scoped, no-unwind placeholder factory or placeholder artifact; drain all produced and retained placeholder state before unloading its epoch.

2. **HIGH — §9, §13. Recursive builds can deadlock despite the documented visit stack.** `Processor::process` and `ProcessContext::read` are synchronous on a bounded worker pool. All workers can block awaiting queued child builds, causing starvation even for an acyclic graph. Separately, simultaneous top-level builds of cyclic assets A and B can each join the other’s existing in-flight job; neither local visit stack contains the other job’s ancestry, so both wait forever instead of reporting the cycle. **Fix direction:** mandate cooperative/inline descendant execution so workers do not park, and maintain a global in-flight wait-for graph or propagate ancestry through joins with cycle detection before waiting.

3. **HIGH — §15, §16, §17. Indirect path handles cannot be implemented through the declared I/O boundary.** `Loader::add_ref_indirect(path)` is promised, while `LoaderIO` can only resolve and subscribe by `AssetUuid`. It has no path-resolution request or path-mapping subscription. Even a pack with `include_path_table = true` has no interface through which the loader can use that table. This contradicts the rule that every loader interaction flows through `LoaderIO`. **Fix direction:** add typed path resolve and path-invalidation operations to `LoaderIO`, with PackfileIO explicitly rejecting them when the path table is absent, or remove indirect handles from this loader surface.

4. **HIGH — §15, §17. The `Dead` and restoration states are unreachable through `LoaderIO`.** `IoEvent::Delta` carries only invalidated UUIDs, and `ResolveResult::Failed` does not distinguish deletion from a build failure, poison, or an ordinary miss. The separate `AssetEvent::Deleted` is not carried by `LoaderIO`. Consequently, a loader cannot know when to enter `ManifestState::Dead`, apply deletion policy, or distinguish a restored asset from recovery after a failed build. **Fix direction:** add versioned typed tombstone/missing/restored results or delta states, distinct from build failure.

5. **HIGH — §15. The `AssetStorage` API cannot enforce asynchronous GPU-gated atomic swaps.** The prose requires `data-ready → committed` gating, but `update` returns only a synchronous `Result`, with no pending ticket or readiness query; `commit` returns nothing and cannot report “not ready.” The loader therefore cannot know when every member of a component is ready before committing atomically. **Fix direction:** have `update` return `Ready` or an epoch/version-bound pending token, add polling/cancellation, and permit component commit only after every token reports ready.

6. **HIGH — §8, §13, §18. Persisted root identity is an unstable configuration ordinal.** §18 says named roots are stable identities, but `RootId(pub u32)` is defined as an index into the configured root list and is serialized into committed `ImportRecord.sources`, read sets, and `FILQ` hashes. Reordering roots or adding one on another checkout can reinterpret existing committed records as referring to a different physical root. The TOML configuration is a name-keyed map, not a stable ordinal list. **Fix direction:** serialize and hash the normalized root name; use numeric interning only as process-local metadata.

7. **HIGH — §6, §7, §11, §13–§15. Publication semantics exist only for identity-validation failure, not other unindexable bundle states.** Malformed containers/JSON, schema-closure failures, unsupported format versions, and similar integrity errors leave the file “uninterpreted,” but the design does not say whether prior asset rows remain visible, become tombstones, or poison relevant queries. Retaining prior rows makes a quiescent current snapshot repeatedly return `Drifted` against the changed bytes; deleting them silently changes query semantics. **Fix direction:** publish an explicit per-physical-file/bundle poison or tombstone for every indexing failure, define effects on prior UUIDs and queries, and ensure current-version resolves return stable `Failed`/`Missing` rather than perpetual drift.

8. **HIGH — §4, §15–§17. Layout attestation is bypassed after a game-module epoch change.** RPC layout compatibility is checked only by `Root.connect`, and pack compatibility only at mount, while `Loader::register_types` explicitly permits successor module epochs to replace descriptors. No API or rule forces reconnect, remount, or revalidation after those descriptors change. Loads can therefore proceed using a registry never compared with the daemon target table or pack closure, contradicting the “fails at open/connect” guarantee. **Fix direction:** bind each IO instance to a `GameModuleEpoch` and descriptor-registry digest, and block loads until every new epoch has re-attested or revalidated the mounted pack.

9. **HIGH — §16. The packfile is not normatively specified enough to be interoperable or recoverable.** There is no archive/manifest byte grammar, magic/version layout, EKey hash algorithm or domain, canonical block-boundary rule, exact zstd codec/version/parameters, blob-extent addressing grammar, or validation rules tying manifests, indices, and archive generations together. “Pinned in the header” does not define the header. Independent writers and readers can produce incompatible files while satisfying the prose, and patch activation cannot be audited for crash consistency. **Fix direction:** define versioned binary grammars for every file and table, domain-separated hashes, canonical ordering/chunking, exact codec parameters, checked offset rules, and the atomic generation-reference protocol.

10. **MEDIUM — §6, §8. Primary inference counts daemon-owned entries and therefore fails for normal first imports.** `primary` defaults to the sole bundle entry, but imported bundles also contain `$settings` and `$record` as ordinary entries. A new importer may legally return one content entry without calling `primary`; there is no prior primary, and the resulting bundle has at least three entries, so path references cannot infer one. **Fix direction:** define sole-entry inference over importer-produced content entries only, or require an explicit primary on every new import that produces content.

11. **MEDIUM — §5, §12. Legal schema states exceed the declared runtime-layout representation.** Logical arrays use `u64` lengths and schema sizes/offsets are `u64`, but `NativeLayoutNode::Array.len`, sizes, strides, offsets, plan ranges, and `fixed_len` are `u32`. The only explicit size rejection concerns the variable section. A legal large Rust array or fixed layout therefore cannot be represented by the descriptor or plan APIs. **Fix direction:** impose extraction-time bounds on every fixed size, offset, stride, array length, and plan index, or widen the artifact and descriptor grammar consistently.

12. **MEDIUM — §6, §12. Blob ordering is not total for nested schemas.** Canonical bundle ordering is specified as `(local_id, field name)`, which aliases blobs in different nested structs, variants, array elements, or map values sharing the same leaf name. `AuthoredValue` permits all those shapes. Artifact blob-table order is likewise only described as ascending/canonical without defining the structural traversal key. Writers can produce different bytes and ContentHashes for the same value. **Fix direction:** define an injective canonical structural path encoding containing fields, variants, indices, and canonical map keys, and use it for both bundle and artifact blob ordering.
